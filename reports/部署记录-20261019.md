## 3. 本次部署中修复的问题

### 3.1 shell 脚本 CRLF

第一次启动时 Linux bash 报：

```text
restart.sh: line 10: set: pipefail: invalid option name
$'\r': command not found
```

原因：Windows 打包时 `deploy/*.sh` 是 CRLF。

修复：

- 把 `deploy/*.sh` 转成 LF；
- 新增 `.gitattributes`：`*.sh text eol=lf`、`*.ps1 text eol=crlf`；
- 重新打 backend 包并重新上传；
- 服务器上脚本现在都是 LF。

### 3.2 21 nt 查询 E 值刚好被 1e-5 挡掉

默认 `blastn` 对 21 nt 完全匹配的 E 值约 `1.09e-05`，而默认阈值是 `1e-5`，导致示例查询 0 hit。

修复：

- `backend/src/blast/ncbi.js`：查询长度 < 30 nt 时自动使用 NCBI 推荐的 `blastn-short`；
- 同一命中的 E 值约 `2.17e-06`，示例现在返回 4 条命中；
- 更长的查询仍用 `blastn`；
- `check-assets.sh` 的输出会显示 `blastTask` 和 hits。

## 4. 当前访问方式

### 方式 A：SSH 隧道（现在就能用）

```powershell
ssh -L 8080:localhost:3618 lab-hj
```

浏览器打开：

```text
http://localhost:8080/PPSD_new/
```

### 方式 B：Apache 反代（需要管理员）

`/home/www/html/PPSD_new` 不存在，`/etc/apache2` 对 `wjj` 不可写，`wjj` 没有 sudo。需要管理员在 `/etc/apache2/sites-enabled/000-default.conf` 的 `</VirtualHost>` 前加：

```apache
<Location "/PPSD_new">
    ProxyPreserveHost On
    ProxyPass http://localhost:3618/
    ProxyPassReverse http://localhost:3618/
</Location>
```

然后：

```bash
apachectl configtest && apachectl graceful
```

配好后地址是 `http://202.195.250.119/PPSD_new/`。
