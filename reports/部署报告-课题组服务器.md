## 2. 第二阶段：完整版（前端 + 后端 + 反向代理）

### 2.0 总体架构

```
浏览器
  │  https?/http://202.195.250.119/PPSD_new/...
  ▼
Apache（80 端口，已有）
  ├─ /PPSD_new/*           → 静态文件 /home/www/html/PPSD_new/（前端 build 产物）
  └─ /PPSD_new/api/*       → 反代到 localhost:3618
                                │
                                ▼
                        Node 22 后端（你的家目录 ~/PPSD/backend/）
                        pglite = PostgreSQL 编译成 WASM，数据在 ~/PPSD/pgdata/
                        （不连服务器任何数据库，不需要数据库账号）
```

### 2.1 在家目录装 Node 22（无需 root）

服务器**没有外网**（nodejs.org、npm 都连不上），所以安装包从 Windows 传上去。
安装包我已经下好：`C:\Users\22345\Downloads\node-v22.23.3-linux-x64.tar.xz`（31MB）。

```bash
# Windows（Git Bash）：
scp ~/Downloads/node-v22.23.3-linux-x64.tar.xz lab:/home/riceUsers/wjj/

# 服务器上（ssh lab 之后）：
cd ~
tar xf node-v22.23.3-linux-x64.tar.xz
mv node-v22.23.3 node22
~/node22/bin/node -v        # 应输出 v22.23.3
```

### 2.2 上传后端和数据（务必打 tar 包，不要直接 scp 目录）

小文件走 VPN 超级慢（scp 传 22 万个文件要 60+ 小时），**一定要先打包成单个文件再传**。

```bash
# Windows（Git Bash），在项目目录 E:\Arborist\Work Files\26.08.11 PPSD\PPSD 下：
tar czf /tmp/ppsd-backend.tar.gz backend          # 约 1.1G（含 node_modules）
tar czf /tmp/ppsd-data.tar.gz -C data raw derived scraped/initiator_scraped.tsv  # 约 145M
scp /tmp/ppsd-backend.tar.gz /tmp/ppsd-data.tar.gz lab:/home/riceUsers/wjj/

# 服务器上：
mkdir -p ~/PPSD
tar xzf ~/ppsd-backend.tar.gz -C ~/PPSD           # 得到 ~/PPSD/backend/
mkdir -p ~/PPSD/data
tar xzf ~/ppsd-data.tar.gz -C ~/PPSD/data         # 得到 ~/PPSD/data/raw、derived、scraped/
```

> ⚠️ 不要上传 `data/reference/`（15G+ 的老站资料），`db:load` 不读它。
> ⚠️ 后端目录里的 `.env`（如有）不要打包上传，服务器上按 2.3 用环境变量。
> ⚠️ `scraped/` 只上传 `initiator_scraped.tsv` 一个文件（6 物种 initiator 灌库用），
>    JSONL 原件和脚本不用传（需要时重新抓，见 `data/scraped/README` 说明）。

### 2.3 灌数据 + 启动后端

```bash
# 服务器上：
cd ~/PPSD/backend
export PATH=~/node22/bin:$PATH
export PPSD_DB_DRIVER=pglite
export PGLITE_DIR=/home/riceUsers/wjj/PPSD/pgdata
export PORT=3618

npm run db:load        # 建表 + 灌 54 万行，约 35 秒，只需执行一次

nohup node src/server.js > ~/PPSD/backend.log 2>&1 &
curl http://localhost:3618/api/health     # 返回 JSON（含数据库版本）即成功
```

以后每次重启服务器后要重新拉起后端，就执行 `~/PPSD/start.sh`（见 2.6）。

### 2.4 构建前端并上传

⚠️ **子路径部署必须配 base**，否则页面全白。已经做好了专用配置
`vite.config.server.mjs`（base=`/PPSD_new/` + API=`/PPSD_new/api`），一条命令：

```bash
# Windows，项目目录下：
npm run build:server    # 产物：dist/ 目录
tar czf /tmp/ppsd-dist.tar.gz -C dist .
scp /tmp/ppsd-dist.tar.gz lab:/home/riceUsers/wjj/
```

### 2.5 请管理员做 Apache 配置（最后一次性麻烦）

**第一步**，发给管理员：

> 麻烦再建一个目录并归属我：
> `mkdir -p /home/www/html/PPSD_new && chown wjj:wjj /home/www/html/PPSD_new`

**第二步**，把 dist 解进去（服务器上）：

```bash
tar xzf ~/ppsd-dist.tar.gz -C /home/www/html/PPSD_new/
```

**第三步**，把下面这段原样发给管理员，加在 `/etc/apache2/sites-enabled/000-default.conf`
里 `</VirtualHost>` **之前**，然后 `apachectl graceful`：

```apache
<Directory "/home/www/html/PPSD_new">
    DirectoryIndex index.html
    FallbackResource "/PPSD_new/index.html"
</Directory>
<Location "/PPSD_new/api">
    ProxyPreserveHost On
    ProxyPass http://localhost:3618/api
    ProxyPassReverse http://localhost:3618/api
</Location>
```

> 这两段是照抄服务器上 SmartRice2/RiceData/RiceSALTnet 的现成写法，
> `FallbackResource` 解决前端 history 路由刷新 404，`Location` 把 API 转给后端。

**第四步，验证**：

```bash
curl -s http://localhost:3618/api/health          # 后端直连
curl -s http://202.195.250.119/PPSD_new/api/health # 经 Apache 反代
```

VPN 内浏览器打开 <http://202.195.250.119/PPSD_new/> —— 完整版上线。

### 2.6 让后端开机自启（可选但建议）

服务器已经稳定运行 168 天，重启很少；但做个保险也不麻烦。服务器上：

```bash
cat > ~/PPSD/start.sh << 'EOF'
#!/bin/bash
export PATH=/home/riceUsers/wjj/node22/bin:$PATH
export PPSD_DB_DRIVER=pglite
export PGLITE_DIR=/home/riceUsers/wjj/PPSD/pgdata
export PORT=3618
cd /home/riceUsers/wjj/PPSD/backend
nohup node src/server.js > /home/riceUsers/wjj/PPSD/backend.log 2>&1 &
EOF
chmod +x ~/PPSD/start.sh
crontab -e     # 加一行：@reboot /home/riceUsers/wjj/PPSD/start.sh
```

> 如果 crontab 不可用，就在 Hyper 里手动 `~/PPSD/start.sh`，一样的效果。

## 3. 日常更新流程

| 场景 | 操作 |
|---|---|
| 只改前端 | 本地 `VITE_API_BASE=/PPSD_new/api npm run build` → 打包 dist → scp → 服务器解压覆盖 `/home/www/html/PPSD_new/` |
| 只改后端 | 上传 `backend/src/`（打包传）→ 服务器 `pkill -f "node src/server.js"` → `~/PPSD/start.sh` |
| 数据更新 | 更新 `data/raw` 或 `data/derived` → 上传 → 服务器 `npm run db:reset`（清库重灌） |
| 只更新 initiator 抓取数据 | 本地 `cd data/scraped && python scrape_loci.py --species all && python convert.py` → 上传新的 `initiator_scraped.tsv` → 服务器 `npm run db:reset` |
| 看后端日志 | `tail -f ~/PPSD/backend.log` |

## 4. 回滚

- 前端：保留旧版 dist  tar 包，解压覆盖即回退；或让管理员把 vhost 里两段配置注释掉再 graceful。
- 后端：`pkill -f "node src/server.js"` 即停，Apache 反代会返回 502，不影响其他站点。

## 5. 注意事项（都是踩过或查过的坑）

1. **不要直接 scp 目录**：小文件在 VPN 上慢到不可用，一律 tar 成单文件再传。
2. **服务器 Node 14 跑不了后端**：代码用了 `process.loadEnvFile()` 和 `import.meta.dirname`（Node 20.11+），必须用家目录的 Node 22。
3. **服务器没有外网**：Node、npm 包都从 Windows 传，别在服务器上 npm install。
4. **vite base 必须配**：子路径部署不配 `base: '/PPSD_new/'` 会白屏；demo 版是 hash 路由不受影响。
5. **别用 3615/3616/3617**：已被占用；也从 3000 起步没意义，3618 起跟现有应用排在一起。
6. **PG 服务器上虽然有（5432/5433 两个实例）但你的账号没有数据库角色**，所以用 pglite，不依赖它。
7. **公网是另一台机器**：cbi.njau.edu.cn 解析到 202.195.242.84，和这台内网机（250.119）不是同一台，内容同步机制未知。本文部署的是内网测试环境；要上公网需要管理员决定同步/切换方案，**并且先跟导师确认数据公开的授权边界**（数据属于实验室，公网可访问+返回真实数据=公开发布）。
8. **initiator 表是 DISTINCT 语义**：与老站 single_cluster 页面一致（官方导出文件里的降解组重复行已在导入时去重）。如果以后拿到 pg_dump 换成真实库，注意保持同样语义。
9. **位点结构图需要老站静态资源**：位点详情页的"位点结构图"读 `plot/{物种}/{span}/{recorder}.jpg`，需要把老站的 `plot/` 目录放到站点根下（见第 6 节清单第 4 项）。不放也能用，页面会显示降级提示。
